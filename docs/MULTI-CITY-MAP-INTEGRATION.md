# Multi-City Map Integration Report

Branch: `multi-city-map-integration` · Date: 2026-07-19

Integrates original maps, 3D maps, and mapped SVG highlight overlays for
New Chandigarh, Mohali, Chandigarh, Aerotropolis (Aerocity) and Zirakpur,
using the existing New Chandigarh overlay system (`PLOTMAP_OVERLAYS` keyed by
registry map id, rendered by `overlay-engine.js`). No second system was added.

## 1. Reference architecture (unchanged)

- `app/plotmap/map-registry.js` — generated by `tools/generate-map-registry.js`
  from `/maps/` (3D / easy) + `/normal maps/` (original proof). Masterplan files
  must contain "masterplan" in the filename; easy↔original pairing is by
  normalized name.
- `app/plotmap/datasets/overlays.js` — `PLOTMAP_OVERLAYS[mapId]` seed entries
  (viewBox + roads[].d + shapes[].paths), consumed through
  `PMOverlayStore.publishedForClient` and mounted by `PlotMapOverlayEngine`.
- Original/3D switch: `state.mapMode` `original`/`markings`; the 3D button
  enables only when the registry map has `easyMapSrc`.
- `modes: ['original']` on a seed entry keeps highlights off the 3D render
  (all five overlays were traced on the original masterplans).

## 4. Overlay placement (alignment)

The Figma exports are group-cropped (the SVG viewBox is the artwork bounds, not
the map frame), so each overlay was registered against its map by pixel-diffing
the annotated composite against the base map and maximizing the fraction of
SVG path sample points landing on overlay ink (2 px dilation) over scale +
offset. The solved affine was baked into the path data exactly (max path
deviation < 0.02 px, point-sample validated), and every entry keeps
`viewBox: '0 0 <imgW> <imgH>'` so Map Studio's coordinate space is unchanged.

| City | Solved placement p = s·u + t | Registration score |
| --- | --- | --- |
| Mohali | s 0.996492, t (28, 103) into 1600×1278 | 0.9965 |
| Chandigarh | s 1.902, t (5, 80) into 1253×984 | 1.00 |
| Aerotropolis | identity (SVG space = original image space; registry jpg is the same image at exactly 1/3) | n/a |
| Zirakpur roads | s 0.987218, t (11, 8) into 1448×1086 | 1.00 |
| Zirakpur blocks | s 0.995, t (163, 164) into 1448×1086 | 1.00 |

## 7. Browser QA (headless Chrome, dev server)

Per city: open original → overlay mounts with correct map id; select road
(glow + drawer); select block/sector (lift + veil + drawer); group A highlight +
banner; clear resets veil/drawer; switch to 3D (correct image, no overlay);
switch back (overlay re-mounts). City switch Mohali→Chandigarh clears the
selection/drawer and mounts the right overlay. Checked at 1440×900, 1366×768
and 1024×768; 3× zoom keeps roads over roads. Console/network: only expected
offline Supabase RPC failures in the sandbox and the pre-existing favicon 404;
no SVG parse errors, no asset 404s.

## 8. Fixes riding along

- `road-spine` (New Chandigarh "Main Spine Road") was invisible to clients on
  live: its drawer row said "Internal main road" and the overlay store leak
  filter (`internal`) suppressed the item. Row text now reads "Main sector
  road".
- Zirakpur blocks render as glass panels (type `sector`) so the proof map stays
  readable under 17 shapes.

## 10. Performance

- Only the active city's original image loads on open; the 3D image loads when
  the 3D mode is selected (single `<img>` swapped per mode).
- New PNGs: 2.1–2.9 MB each (unchanged quality; no recompression).
- overlays.js grew to ~65 KB (one file, cached; version bumped to v=11).
- Overlay engine unmounts the previous overlay root on every mount; repeated
  city switching reuses the same map layer.

## 11. Constraint compliance

- No Supabase SQL, no migrations.
- No changes to device locking, auth, trial analytics, or developer controls.
- No Map Studio drawing-engine changes; `overlay-engine.js` untouched.
- No fabricated geometry — every path comes from the delivered SVGs; the only
  transformation is the solved exact affine (validated < 0.02 px).
- SVGs not redrawn; originals preserved byte-for-byte in `public/plotmap-assets/`.
- Original map proportions untouched (no image edits anywhere).
