Sources: `app/plotmap/map-registry.js` (5472 lines, **generated**, 170 map entries),
`app/plotmap/app.js` (2213), `app/plotmap/overlay-engine.js`, `app/plotmap/overlay-capture.js`,
`app/plotmap/datasets/{map-config,tricity.dataset,sector-pins,overlays}.js`,

`/normal maps/` (Original), `/public/plotmap-assets/`. Manifest: `manifests/map-assets.json`.

> The map engine is the **hardest, most domain-specific** subsystem. It is proven and must
> be **isolated and ported, not casually rewritten** (`21`). This doc captures the contracts
> a V2 agent needs; the full pixel-math internals live in `app.js`/`overlay-engine.js` and are
> ported wholesale via `migration-kit/maps/` (see that folder's manifest for exact files).

## Map registry contract (`window.PM_MAP_REGISTRY`)

Generated by `tools/generate-map-registry.js` — **do not hand-edit**. Shape:
`{ version, generatedAt, sourceFolders:{ easy:'/maps/', original:'/normal%20maps/' }, maps:[…] }`.

Each map entry (`VERIFIED-CODE` `map-registry.js:10-70`):

| Field | Meaning |
|---|---|
| `id` | stable map id, e.g. `masterplan-aerocity-mohali-masterplan` |
| `title` / `displayName` | human label |
| `type` / `mapType` | `masterplan` \| sector/block map |
| `area` / `city` / `sectorOrBlockName` | location taxonomy |
| `easyMapSrc` / `originalMapSrc` | URL-encoded asset paths (may be null) |
| `hasEasyMap` / `hasOriginalMap` | availability flags |
| `overlays` / `overlayCount` | overlay descriptors |
| `dimensions` / `easyDimensions` / `originalDimensions` | pixel sizes for correct scaling |
| `matchKey` / `asset` / `easyFileName` / `originalFileName` | linking + file names |
| `status` | `active` |

**Two renderings per map:** *Original Map* (raw scan, e.g. a `.jpg`) and *Easy Map*
(cleaned `.png`). Both carry their own dimensions so the engine scales overlays/pins without
distortion. `VERIFIED-CODE`.

## Datasets
- `datasets/map-config.js` — engine configuration.
- `datasets/tricity.dataset.js` — the Tricity dataset (areas/sectors).
- `datasets/sector-pins.js` — pin definitions per sector.
- `datasets/overlays.js` — overlay geometry.
- `geo.json`, `map-assets.manifest.json`, `map-assets.grouped.json` — geo + asset manifests.

## Overlays, coordinates, pins, property placement
- `overlay-engine.js` renders overlays over the chosen map at correct scale.
- `overlay-capture.js` supports authoring overlays (Map Studio).
- `overlay-store.js` (global `PMOverlayStore`) persists overlays; it reads
  `plotmap_dealer_id` for tenant scoping (`overlay-store.js:33`). `overlay-engine.js` also
  reads it (`:417`).
- Property→map linking stores pins/coordinates in the `pins`/`mapDrawings` collections.

## Known risk (see `19`)
**Map cropping / distortion.** `HISTORICAL`/`REPORT-CLAIM`: maps must not be cropped or
distorted; Original vs Easy toggle, zoom, and "Fit Map" must all preserve aspect ratio. The
per-rendering `dimensions` fields exist precisely to prevent this. V2 acceptance test: load a
masterplan + a sector map, toggle Original/Easy, zoom, Fit Map — assert no crop/distortion.

## V2 decision
**REUSE/ADAPT — port wholesale, isolate cleanly.** Move the registry generator, the registry
data, the datasets, the overlay engine/capture/store, and the map assets into a self-contained
V2 `maps` package with a **stable public API** (`getMaps()`, `getMap(id)`, `renderMap(el,id,{mode})`,
`renderOverlays(...)`). Do not rewrite the pixel math. Keep the generated-file discipline
(registry is generated, never edited). Self-host assets (no external CDN dependency).
